# 任务自适应思考深度

v0.1.2：会话信息查询短暂失败时进行最多两次有界重试，并在失败日志中记录阶段及错误类别，不记录消息内容。正式版新聊天中，Agent 代发首条消息将档位从 `medium` 降至 `low`；用户在同一聊天直接输入下一条消息时，分类器再次调用并保持 `low`。另一次界面新建聊天后，用户直接发送首条「1」也完成分类，会话从 `medium` 降至 `off`，Pi 回读 `off`。但该轮模型回复仍包含 thinking 内容；原始 provider 请求参数未抓取，不能据此认定上游已关闭思考。状态工具的记录仅在插件当前进程内保留，重载后会清空。

HanaAgent 0.449+ 的 full-access 插件。对明确启用的 Agent，在新的用户消息进入正式回答前，由 Hana 当前配置的 **utility 文本模型**结合少量近期对话评估任务难度，再通过 Hana 的 `session:update` 改变**当前会话**的思考档位。Hana/Pi 负责按所选聊天模型映射参数；插件不改聊天模型、provider 配置或 Hana 源码。

## 启用与操作

1. 在设置 → 插件确认本插件已加载；在设置 → 供应商确认当前 Agent 使用的 utility 模型及其供应商。默认所有 Agent 均未启用自动判断。
2. 进入要使用的 Agent，建议在安装后新建聊天，发送：`请调用 adaptive-thinking-plugin_adaptive_thinking_control，传入 {"mode":"on"}，为此 Agent 开启自适应思考。` 等待工具确认；从**下一条**用户消息开始自动选档。
3. 一个 Agent 启用一次即可；在新聊天中无需重复输入 `mode:on`。发送普通问题即可使用。要检查状态，发送：`请调用 adaptive-thinking-plugin_adaptive_thinking_status，查看自适应思考状态。` 注意已开启时，这条用户消息本身也会触发一次分类；状态工具不会额外调用模型。
4. 手动点击 Hana 原生档位按钮会暂停**本会话**的自动判断。要恢复，再调用控制工具传 `{"mode":"on"}`；`{"mode":"off"}` 仅暂停本会话，`{"mode":"agent_off"}` 停用此 Agent。

Hana 0.449 的设置 → 插件 → 配置弹窗仅显示全局配置字段，本插件的开关是 per-agent/per-session，因此**不要在该弹窗里找开关**。若旧聊天找不到插件工具，新建聊天再发上述指令。若模型本身不支持思考或会话属于后台活动、子 Agent、插件私有会话，插件保持原样。

普通问候可以降档，复杂排错或跨文件核对可以升档，换回简单话题后会再次降档。用户在消息里明确要求本轮档位时分类器应优先采用；要求“以后都用某档”时会设档并暂停自动模式。语义判断可能误判，手动选择始终可以覆盖。

## 分类器与隐私

- 分类使用当前 Agent 的 **utility 模型及其 provider**，不是正在聊天的模型；在 Hana 的模型设置中先确认 utility 的供应商。若两者供应商不同，当前任务和有限的近期对话会发往 utility 所在供应商。每条启用的用户消息最多发起一次分类调用，产生相应费用和延迟。
- 仅发送当前用户消息的最多 2600 字，以及最近最多四段用户/助手文本（每段最多 850 字）。不读取工具输出、系统提示、图片或文件内容；用户主动粘贴进消息的文本仍可能进入分类请求。
- 默认 3.5 秒超时，输出不合法或调用失败时保留原档位并继续回答。SDK 尚未提供此调用的取消信号，超时后供应商请求可能仍在后台完成并计费。
- 插件只在内存里留最近一次档位、时间、简短标签和失败码；不落盘原始消息。开关及手动暂停标记由 Hana 的插件配置保存。使用记录可在 Hana 的模型调用用量记录中按插件识别。
- 档位更新后分别记录会话写入结果与 Pi 即时回读值。两者不一致时状态工具会提示「档位回读不一致」；若宿主未提供可核实的会话档位，会提示「未核实」。这些记录不能代替模型请求参数的核查。

## 开发验证

源码直接可安装，无需 npm 依赖或构建；`npm test` 运行纯逻辑与扩展事件测试。通过 Hana 插件开发态工具安装该目录时需要 `allowFullAccess: true`；诊断加载状态后运行 `smoke-status` 场景。场景只验证工具加载，不会产生模型调用。

真实请求验证需先为 Agent 启用一次自动选档，随后在新会话中发送消息，并核对插件判定日志、会话档位、Pi 回读和请求的实际 reasoning 参数。原生档位设置只对之后发出的请求生效；同轮工具之后的模型请求沿用本轮已选档位。对旧版本或未来 SDK 的事件、档位保存机制变动需重新验证。
